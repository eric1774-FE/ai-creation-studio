## 1. Manifest 与提示词契约

把执行提示词写成生产说明，不写文学赏析、来源说明或广告文案。所有数据使用 `story-asset-manifest/v2`，不创建 `K` 资产。

别名表的每项只使用 `alias`、`canonical` 和可选 `note`；一个别称写一项，不使用 `variants` 数组。只有 `W` 资产允许 `subtype: costume/hair/makeup`，包括 `A` 在内的其他类型不得写 `subtype`。

### 1.1 提示词对象

每条 `prompts[]` 必须包含：

- `id`：全局唯一，使用 `<asset-id>-<version>-<purpose>`，例如 `C01-v1-face`。
- `label`：供人识别的中文名称。
- `mode`：`generate` 或 `edit`；`edit` 必须有输入。
- `input_refs`：每个输入写 `source_kind: reference_input/prompt_output`、`ref_id` 和具体职责 `role`。引用必须存在，不得自引用、重复或成环。
- `output_spec`：`media_type: image/audio` 和正整数 `count`；图片必须有 `layout`、`aspect_ratio`；声音按需有 `duration_seconds`、`loopable`。
- `text`：脱离 Manifest 仍可复制执行的完整中文提示词。
- `text_en`：必填的完整英文提示词，与 `text` 逐项保持生产约束一致。

提示词正文与 `output_spec` 必须一致。生图第一句明确资产类型、图片数量、主体或视图数量、顺序、排列、取景、背景和基础布光；编辑第一句明确各输入职责、只允许改变的范围和必须保留的内容。

视觉提示词固定按“任务 → 主体与状态 → 视图与构图 → 可见形态与材料 → 环境与光线 → 一致性约束 → 风格 → 负面约束”组织。声音提示词按“任务 → 声源与状态 → 时长与结构 → 音色和动态 → 空间与同步 → 风格 → 负面约束”组织。

每条中文正文末尾明确写 `风格：` 和 `负面约束：`；英文正文对应写 `Style:` 和 `Negative constraints:`。视觉提示词展开当前 `G01` 中与该资产有关的线条、材质、色彩、光线或渲染规则；声音提示词写可执行的表演、录音或声音设计风格，不混入视觉规则。负面约束只列该任务最可能失败的内容。

生成前按以下五项判断重复：资产身份、版本状态、生产用途、输入职责、输出规格。五项一致时合并为一个资产版本或一条提示词，由实体和阶段复用同一引用；任一项不同则不能合并，并在 `id`、`label` 和正文开头明确主体、状态或交付差异。禁止仅更换 ID、标签或少量同义词后保留相同正文。

中英文执行提示词只保留模型需要执行的内容：

- `text` 使用专业中文，`text_en` 使用自然的英文影视与资产制作术语，保留必要专名。
- 英文按生产含义重写，不机械逐字翻译；数值、单位、主体数量、视图顺序、身份锚点、材料、输入职责、输出要求和禁止项必须与中文逐项一致。
- 重复关键身份、结构和风格锚点，不写“同上”“参考前文”。
- 不写 `inference`、`estimated`、“合理推断”“原文明确”等来源或状态标签；这些只保存在 `facts`。
- 不写 Midjourney 参数、Stable Diffusion 权重或其他模型专属语法。
- 仅保留针对高概率失败的禁止项，不堆砌几十条否定词。
- 同一语言的完整提示词正文不得与另一提示词完全相同。

### 1.2 事实

每项事实独立保存为：`key/value/unit?/source/status/evidence/source_locator?`。

- `source`：`user/source_text/style_bible/inference/creative`。
- `status`：`confirmed/estimated/pending/conflict`。
- `source_text` 必须有 `source_locator`；所有事实必须有具体 `evidence`。
- 稳定事实放资产级 `facts`，只属于某个状态的事实放版本级 `facts`。
- 原文冲突使用 `status: conflict` 并写入 `pending_questions`，不要静默选择。

### 1.3 用户参考图

每张用户图片建立 `reference_inputs` 记录，`role` 只使用 `identity/style/costume/scene`。

- 身份图：允许影响脸、原有可见身份标记和用户指定的身体特征；禁止输出图自行复制背景、版式或未授权服装。
- 风格图：允许影响线条、着色、材质、色彩或光线；禁止复制参考图人物身份、服装、文字和场景内容。
- 服装图：允许影响服装结构、材料和颜色；禁止影响人物脸、身材、发型、背景和姿势。
- 场景图：允许影响空间结构、材料和固定陈设；禁止成为人物身份或服装来源。

同一参考图承担多个职责时建立多个记录，分别限定允许和禁止影响；不要用一句“参考图片”把职责混在一起。

### 1.4 可见性检查

视觉提示词中的每个形容词必须能用形状、数量、比例、姿态、表情、材料、颜色、光源、表面状态或空间关系验证，否则转译或删除。

不得直接使用：

- `体现、传达、营造、象征、暗示、充满、带有……感、给人一种……感觉`。
- `专业、高级、震撼、唯美、史诗、电影级、电影感、氛围感、神秘、危险、压迫、优雅、有气场、圣洁、邪恶、荒诞`。
- 成语、诗句、隐喻、人格化描述和无法直接成像的文化梗。

媒介名称可以保留，但不能代替可见规则。

## 2. 修辞转译

文学修辞可保存在非执行说明中；执行提示词只使用可见或可听结果。

| 原文表达 | 执行层转译 |
|---|---|
| 悲伤、心碎 | 眼睑、视线、嘴角、肩颈、动作速度、冷暖和负空间 |
| 倔强、不屈 | 直视、下颌微抬、双手收紧、重心稳定 |
| 孤独 | 单一主体、小比例人物、大面积空旷空间、稀疏环境声 |
| 压迫 | 狭窄空间、近距离遮挡、低照度、深阴影、持续低频 |
| 危险 | 不稳定物体、异常静止、警觉视线、尖锐瞬态或远处低频 |
| 时间流逝 | 褪色、磨损、灰尘、锈蚀、植物生长、季节和光线变化 |
| 像暴雨中的玫瑰 | 若只是比喻，不新增玫瑰；改为湿发、破损衣料、红色锚点和风雨中的稳定姿态 |

若视觉象征会新增剧情元素，省略象征，只转译结果。

## 3. 全局视觉圣经与媒介模块

`G01` 固定包含：

- `render_mode`：`live_action/2d_comic/3d_animation/hybrid`。
- 时代地域、社会与技术水平。
- 生产设计材料及新旧程度。
- 主色、中性色、强调色、饱和度和冷暖关系。
- 真实或绘制光源、光质、反差和阴影保留。
- 清晰度、颗粒、线条、纹理和空间层次。
- 时代、媒介和审美禁止漂移项。

媒介未指定时先询问媒介；媒介确定后才在该媒介内给三套风格候选。选定后只使用一个模块：

### 3.1 真人写实 `live_action`

每条包含真人的生图提示词按可见范围加入：

```text
使用真实人物摄影式呈现。可见皮肤保留细小毛孔、细软面部绒毛、轻微自然肤色差异和符合年龄的细纹；眼球表面有自然湿润反光，头发与眉毛可辨单根毛发，光线在皮肤、眼睛与发丝上形成符合光源方向的高光、半影和阴影。禁止蜡像或塑料皮肤、瓷面磨皮、过度美颜、CG 渲染和玩偶质感。
```

真人编辑提示词加入：

```text
保持输入人物的自然皮肤纹理、细小毛孔、细软面部绒毛、符合年龄的细纹、眼球湿润反光、发丝和原有可见身份标记；不要磨皮、美颜或把皮肤改成蜡像、塑料或瓷面表面，不得新增痣。
```

`痣`只能来自用户或原文；位置或形态不明时使用事实 `pending`，不得自行新增。编辑图只保留输入中已有痣。

### 3.2 二维漫剧 `2d_comic`

`G01` 必须锁定并在相关提示词重复：

- 外轮廓和内部结构线的粗细关系、线条颜色、转折和收笔方式。
- 面部简化层级、眼睛占脸宽比例、鼻口表达方式、头身比。
- 头发分组数量、发束形状、发梢和高光块规则，不绘制真人式逐根发丝。
- 固有色色块边界、渐变使用范围、明暗分层数量、投影边缘软硬。
- 衣料、皮肤、金属、木石等材质的图形化纹理密度。
- 透视和空间层次规则；禁止混入真人皮肤毛孔、摄影噪点、三维塑料高光或另一套线稿体系。

### 3.3 三维动画 `3d_animation`

`G01` 必须锁定：

- 角色和场景几何的写实或风格化程度、曲面转折和边缘锐度。
- 皮肤或表面的着色方式、材质粗糙度关系、次表面或非写实着色范围。
- 毛发使用发片、发束几何或可辨发丝中的哪一种，禁止跨资产切换。
- 直接光、间接光、接触阴影、体积层次和环境反射的统一行为。
- 禁止突然出现二维描边、真人摄影噪点或不同的材质渲染体系。

### 3.4 混合风格 `hybrid`

必须写明“主结构媒介”和“次级表面媒介”，例如三维几何结构配二维赛璐璐着色。所有资产保持同一主次关系；禁止角色用二维结构而场景改用真人摄影结构，或不同版本交换主次媒介。

## 4. 角色与服装妆发

### 4.1 角色分级与事实

- A：主角、核心对手、反复出现且要求身份一致的角色。
- B：有姓名或明确剧情作用的次要角色。
- C：群演、一次性角色或背景职业群体。

`C` 只保存不可变身份：年龄、骨相、脸型、五官比例、肤色、原文明示的稳定标记和发际线。发型、发色、胡须、妆容和彩绘分别保存为 `W` 的 `hair` 或 `makeup` 子类型。面部图可以呈现当前造型，但后续编辑只把 `C` 锚点视为不可变身份。

### 4.2 身体数值锚点

- 原文或用户给出数值时原样保留，按来源记录事实。
- 人类或类人 A/B 缺少身高或体重时，依据年龄、时代地域、职业、活动量、原文体型线索和角色关系，为缺失项选定一个相互合理的整数值。
- 推断数值在 `facts` 中使用 `source: inference/status: estimated`；执行提示词只写“身高约 X 厘米、体重约 Y 公斤”和至少两项可见比例，不写来源标签，不输出 BMI。
- 可见比例至少从以下选择两项：肩宽与头宽比、腿长占身高比、腰胯宽度关系、躯干与四肢的肌肉或皮下脂肪分布。
- C 级人群使用明确数值区间，不为每个群演虚构单值。
- 非人类、机械体或特殊变形体不强制公斤数，使用整体高度或长度、头身比、结构宽度以及与人、门、载具或道具的尺度关系。原文或用户有重量时保留。
- “中等身材、偏矮、高挑、偏瘦、壮实”不能代替数值和可见比例。
- 数值一经选定，在所有版本中保持，除非剧情或用户明确修改。

### 4.3 A/B 级两步身份流程

第一步提示词 ID 使用 `Cxx-vx-face`，`mode: generate`；若有用户身份参考图，通过 `reference_input` 引用。

```text
生成一张角色面部身份基准图。画面只呈现一名[身份、年龄、地域]角色的四分之三头肩特写，头顶、下颌和肩线完整入画；眼平相机，纯净中性背景，柔和均匀工作室布光，中性表情，眼睛自然睁开。[不可变骨相、脸型、五官比例、肤色、皮肤或绘制表面规则、发际线、原文明示的稳定标记]。[当前 W-hair 与 W-makeup 造型，只作为当前造型，不加入不可变身份锚点]。穿无图案的中性基础上衣，只显示简洁领口和肩部。[所选媒介模块]。除非原文或用户明确，不添加首饰、头饰、面部彩绘或痣。禁止额外视图、全身、手部、夸张表情、复杂环境、身份漂移、文字和水印。
```

第二步 ID 使用 `Cxx-vx-fullbody`，`mode: edit`，以第一步 `prompt_output` 为唯一面部身份输入；当前妆发按对应 W 资产说明。

```text
编辑输入的角色面部身份基准图。输入图只作为人物面部身份、年龄、骨相、五官比例、肤色、表面质感、发际线和稳定面部标记的基准；不要复制其裁切、姿势、背景或版式。根据[身高约 X 厘米、体重约 Y 公斤、至少两项可见身体比例]扩展为一张横向完整人物四视图设定板。画面只呈现同一角色，按正面、四分之三侧面、标准侧面、背面从左到右等比例排列；每个视图头顶、双手和双脚完整入画。四个视图使用同一中性站姿、脚底基线、人物缩放、相机高度、透视和身体比例；只改变观察方向。使用[当前 W-hair、W-makeup 和服装]，四个视图保持同一身份、造型、服装、表情和光线；背面连续还原发型、头部轮廓、肩背和身体比例，不虚构面部。[所选媒介模块]。禁止额外人物、额外视图、视角错序、换脸、年龄变化、身体比例漂移、姿势变化、裁切、文字和水印。
```

A 级基础服使用不透明、无图案、无装饰的中性灰贴身上衣、及踝长裤和贴地无跟基础鞋。B 级默认穿故事服装；反复换装或用户要求母版时改用基础服。

### 4.4 精确身高标尺

默认关闭。只有 `height_cm` 的 `status: confirmed`，或用户确认原先估算值后，才能把数值写入标尺和“身高标注要求”。`estimated/pending/conflict` 不得成为准确标尺。

启用时四个全身视图共用脚底基线、缩放、相机高度和透视；最左侧增加无数字的中性灰刻度线和头顶辅助线。准确数字单列供后期排版，不依赖生图模型绘字。

### 4.5 W 子类型

- `costume`：服装、鞋履和明确配饰。
- `hair`：发型、发色、胡须及其版本。
- `makeup`：妆容、面部彩绘和明确状态。

三种子类型分别建立资产和编辑范围。换装不得改发型、妆容、脸或身材；换发不得改脸、妆容和服装；换妆不得改骨相、发型和肤色。

A级每套故事服装默认输出隐形人台结构图和四视图换装编辑提示词；B级只在启用换装母版时采用。

```text
生成一张横向服装结构设定板。只呈现同一套完整服装，按正面、标准侧面、背面从左到右等比例排列，全部服装和鞋履完整入画；纯净中性背景，均匀工作室布光。使用不可见人体支撑保持真实穿着体积，[层次、结构、面料、颜色、工艺、合身程度、开合、装饰、新旧和污损]。三个视图保持同一尺度、层次、材料和连续结构。禁止人物、皮肤、脸、头发、头部、手脚、可见人台、衣架、平铺、额外服装、文字和裁切。
```

换装提示词 `mode: edit`，同时引用角色四视图和服装结构图的 `prompt_output`，逐视角匹配结构；只替换服装范围，锁定身份、脸、发型、妆容、肤色、身高、身体比例、站姿、视角、版式、背景和光线。

## 5. 场景、道具、载具与生物

### 5.1 场景分级

场景提示词都是无人生产资产，不是分镜。固定写清时代地域、空间用途、尺度、入口、动线、主材料、固定陈设、表面状态、生活痕迹、适用 E/L 和媒介模块。

#### A 级核心场景

满足任一：出现至少三个阶段、作为反复主场景、承担必须保持方向连续性的核心事件。输出三条：

1. `Sxx-vx-layout` 空间布局：`generate`，俯视空间布局，标明入口、出口、固定分区、动线、不可移动陈设和相对尺寸；不生成故事角色或依赖文字标签。
2. `Sxx-vx-four-directions` 四方向参考：`edit`，引用布局产物，按入口朝内、左侧、正对入口、右侧四个眼平视图横向排列，固定门窗和陈设位置。
3. `Sxx-vx-master` 中性主视图：`edit`，引用布局与四方向产物，生成无人三分之四空间主视图，锁定空间关系、材料和固定陈设。

#### B 级重复场景

出现两个阶段。生成一条横向正向与反向空间参考提示词，两个眼平视图使用同一相机高度、尺度、门窗、材料和固定陈设。

#### C 级一次性场景

只出现一次。生成一张无人三分之四置景参考图；需要比例时只使用无身份简洁人形。

昼夜、天气、损毁和改造使用版本或 E/L/F，不复制整个场景资产。

### 5.2 道具

以“生成一张道具隔离参考图”开头，写明物体和视图数量、实际尺寸或尺度关系、材料、工艺、年代、颜色、表面状态、功能部件、归属和剧情状态。默认三分之四角度、完整入画、中性背景、均匀光线；正反面均有信息时输出双视图。准确文字单列供后期叠加。

### 5.3 载具与生物

- 载具：多视图设定板，写清年代、尺寸、结构、材料、涂装、磨损和关键方向。
- 动物或怪物：写清物种或结构、尺度、表面、步态和身份锚点；反复出现者使用多视图。非人类不套用人类公斤数规则。
- 特殊群体：写清主体数量、排列、共同造型规则和允许差异。

## 6. 环境、灯光与特效

### 6.1 环境 `E`

写明兼容场景编号、时段、季节、天气、风向强度、空气水汽或颗粒、地面与表面反应、能见度和远近层次。最终 S 提示词展开完整信息，不写“应用 E01”。

### 6.2 灯光 `L`

写明兼容场景、真实或绘制光源、方向、光质、色温关系、照度倾向、反差、阴影、实用灯和强调色；行为必须符合当前媒介模块。

### 6.3 特效 `F`

以“生成一张特效概念参考图”开头，写明主体数量、取景和背景，再写来源、物理媒介、尺度、阶段、方向、速度、颜色、接触关系、对光线和表面的影响及结束状态。区分实拍与数字效果，不生成危险制作操作。

## 7. 声音

声音不得出现在视觉提示词中。声音提示词使用 `output_spec.media_type: audio`。

- `A-VO`：角色编号、年龄感、音域、音色、口音、语速、吐字、气息、情绪控制、表演强度、录音洁净度和禁止项。
- `A-AMB`：地点时段、前中后景声源、远近、密度、混响、动态、循环衔接和安静区域。
- `A-FOL`：动作、接触材料、力度、节奏、距离、空间、时长、瞬态和衰减。
- `A-SFX`：叙事功能、声源或合成逻辑、频率重心、起音、主体、尾音、位置、时长和同步点。
- `A-BGM`：故事阶段、时长或循环、类型语境、BPM、拍号、调式、核心乐器、能量曲线和对白混音空间。
- `A-SIL`：持续时间、抽走声层、保留微弱现场声、动态下降和恢复点。

声音类别只编码在 `A-VO/A-AMB/A-FOL/A-SFX/A-BGM/A-SIL` 的资产 ID 中，不添加 `subtype`。

不要只写“磁性、好听、史诗、感人、悬疑、震撼”。落实为音域、速度、调式、音色、节奏密度、动态和空间。

## 8. 连贯性

根节点 `continuity` 是阶段对象数组，不创建 `K` 资产。

每阶段固定包含：

- `stage_id`：稳定唯一 ID，例如 `stage-01`。
- `label`：人类可读阶段名。
- `source_locator`：章节、场次或原文位置。
- `asset_refs`：当时适用的角色、服装、妆发、道具、场景、环境、灯光、特效和声音版本。

状态变化只建立受影响资产的新版本。后续提示词重复当前版本锚点；同一版本可以出现在多个阶段。

实体引用同时承担 HTML 资产分类的归属来源：

- 角色实体引用角色本体、服装、妆发、随身道具、角色声音和专属载具或生物。
- 场景实体引用场景本体、场景道具、环境、灯光、特效、环境声音和场景载具或生物。
- 同一共享资产可被多个实体引用，不复制资产或提示词；没有明确归属的资产放入 `standalone_asset_refs`。

## 9. 质量检查

交付前逐项确认：

- 已读完整故事并处理别名、原文冲突和用户参考图职责。
- 已锁定唯一 `render_mode`，执行提示词没有混入其他媒介模块。
- 十类 `asset_type_coverage` 完整，数量与实际资产一致；没有 `K` 资产。
- 别名逐项使用 `alias/canonical/note?`；只有 W 资产带合法 `subtype`，声音功能通过 A 类编号表达。
- 每项事实均有合法 `source/status/evidence`；`source_text` 有定位；来源标签未进入执行提示词。
- A/B 人类或类人角色有单一身高体重数值和至少两项可见比例；C 级人群有数值区间；非人类未被强制赋予公斤数。
- 只有 `confirmed` 身高进入准确标尺。
- C 资产只锁不可变身份；发型、胡须、妆容和彩绘已归入正确 W 子类型。
- A/B 两步身份提示词有唯一 ID 和正确依赖；换装同时引用角色与服装产物。
- A/B/C 场景按等级输出规定的布局、方向和主视图提示词及依赖。
- 每条提示词有合法 `mode/input_refs/output_spec/text`，不存在重复、悬空、自引用或循环。
- 重复候选已按资产身份、版本状态、生产用途、输入职责和输出规格完成合并或明确区分；不存在不同 ID 对应相同正文。
- 新提取结果的每条提示词都有非空 `text_en`；中英文的数值、身份锚点、视图顺序、输入职责、输出要求和禁止项逐项一致。
- 每条中英文正文分别包含明确的风格与负面约束段；声音提示词使用声音风格，不混入视觉风格。
- 每个资产版本已归入实体、状态或独立资产区；共用与状态引用不重复。
- 角色与场景的服装妆发、道具、声音及其他关联资源已引用到正确实体；共享资产没有被复制。
- `continuity` 按阶段保存对象和有效资产版本引用。
- 每条提示词自包含、开头明确任务与交付形式，没有未转译抽象词、视听混写或模型专属参数。
- 真人、二维、三维或混合媒介的表面、线条、材质和光线规则分别完整且不串用。
- 准确文字已单列，长文案未被当作可靠生图内容。
- `quality_checks` 只记录语义检查；结构通过必须来自渲染器 `--validate-only`。
