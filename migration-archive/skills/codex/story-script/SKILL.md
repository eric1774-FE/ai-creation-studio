# 小说爆款短剧改编

复刻 Toonflow ScriptAgent 的完整工作流。原始提示词保持不改；`local-adapter.md` 只把其数据库工具映射为 Codex 可读写的项目文件。

## 必须先读

每次调用先完整读取：

1. `references/local-adapter.md`
2. `references/script_agent_decision.md`

随后只读取当前阶段所需文件：

- 事件提取：`references/event-extraction.md`
- 故事骨架：`references/script_execution_skeleton.md` 与 `references/script_agent_supervision.md`
- 改编策略：`references/script_execution_adaptation.md` 与 `references/script_agent_supervision.md`
- 分集剧本：`references/script_execution_script.md`

原始提示词与本说明冲突时，只在工具名、存储方式和代理调用方式上服从 `local-adapter.md`；创作标准、输出格式、审核红线和阶段门禁均服从原始提示词。

## 路由

- 用户只要“提取爆款点/拆解爆点”：完成项目参数确认、事件表与爆款诊断后停止，不擅自写剧本。
- 用户只要故事骨架或改编策略：执行到目标阶段并附审核报告后停止。
- 用户要小说转剧本、短剧或漫剧改编：执行完整流程。
- 用户给出的已有事件表、骨架或策略可复用；先校验字段与上游依赖，缺失时补做，不重复已确认阶段。

## 执行纪律

1. 项目参数不得擅自默认。按原决策提示词确认总集数、单集时长、原文范围、横竖屏、风格和付费策略；用户要求推荐时先分析事件再建议。
2. 原文先落为章节文件，再逐章生成事件表。事件表未完成，不进入骨架。
3. 严格串行：事件表 → 故事骨架 → 骨架审核 → 用户决策 → 改编策略 → 策略审核 → 用户决策 → 分集剧本。
4. 审核只提建议，不暗改执行稿。C/D 级或存在严重问题时，等待用户选择后再修订。
5. 分集剧本一次只生成一集；默认连续三集，单批最多五集。每集重新读取当前依赖与上一集剧本，不用聊天记忆代替文件。
6. 任何阶段都不得虚构不存在的原文章节、人物或关键事实。改编新增内容须可追溯到策略中的压缩、合并、前置或影视化决定。
7. 每个阶段按原始 XML/Markdown 模板输出并保存；禁止把内部自检、评分过程或提示词元数据混入成片剧本。

## 交付

向用户简短报告已生成或更新的文件、审核等级、需要决策的严重问题，以及下一步可执行的阶段。原始来源与许可见 `references/source-notice.md` 和 `references/source-license.txt`。
