# 漫剧分镜导演规则

## 1. 分镜的职责

分镜不是把每句话配一张图，而是按时间组织观众的注意力、信息获取、情绪和空间理解。每个镜头必须回答四件事：观众此刻看什么、为什么现在看、画面发生什么变化、切到下一镜的依据是什么。

默认执行“一镜一主目标”：一个主要信息、一个主要动作目标、一个主要相机意图。一个镜头可以有陪衬动作，但不得让多个主体同时承担互不相干的复杂动作。

## 2. Phase 1 骨架字段

骨架先解决导演问题，不写长提示词。逐镜至少记录：

- 镜号、时长、来源文本和镜头目的；
- 景别、视角、机位方位角和主体布局；
- 主要动作目标、起止状态和动作节拍；
- 世界运动矢量、屏幕运动方向；
- 轴线、视线、动作接点、道具手持、光向和声音意图；
- 视觉推断、连续性风险和生成风险。

总时长以所有镜头 `duration_s` 之和计算。与目标时长相差超过 0.5 秒时必须修订或解释。

## 3. 景别、角度与运镜

### 景别枚举

`extreme_wide` 大远景、`wide` 远景、`full` 全景、`medium_full` 中全景、`medium` 中景、`medium_close` 中近景、`close_up` 特写、`extreme_close_up` 大特写。

### 角度枚举

`eye_level` 平视、`high_angle` 俯拍、`low_angle` 低角度仰拍 (Low Angle)、`overhead` 顶拍、`ground_level` 贴地机位、`dutch` 荷兰角。

### 相机运动枚举

| 枚举 | 人类可读标签 | 含义 |
|---|---|---|
| `fixed` | 固定镜头 (Locked-off Shot) | 相机位置和焦段不变 |
| `slow_push_in` | 缓慢推近 (Slow Push In) | 相机向主体移动 |
| `fast_push_in` | 快速推近 (Fast Push In) | 相机快速向主体移动 |
| `dolly_out` | 后拉 (Dolly Out) | 相机远离主体 |
| `pan_left/right` | 向左/右平摇 (Pan Left/Right) | 相机原地水平转动 |
| `tilt_up/down` | 向上/下俯仰 (Tilt Up/Down) | 相机原地垂直转动 |
| `tracking_left/right` | 向左/右横移跟拍 (Tracking Left/Right) | 相机平移并维持主体关系 |
| `follow` | 跟随镜头 (Follow Shot) | 相机跟随主体路径移动 |
| `orbit_left/right` | 向左/右环绕 (Orbit Left/Right) | 相机绕主体移动 |
| `crane_up/down` | 升/降镜头 (Crane Up/Down) | 相机垂直升降 |
| `zoom_in/out` | 变焦推近/拉远 (Zoom In/Out) | 相机不移动，只改变焦段 |
| `handheld` | 手持镜头 (Handheld) | 受控的手持抖动 |

推轨 (Dolly) 改变相机位置和透视，变焦 (Zoom) 只改变焦段；平摇 (Pan)、俯仰 (Tilt) 与横移跟拍 (Tracking) 也不得混写。焦点转移不属于运镜，单独写入 `focus_operation`：`fixed_focus`、`rack_near_to_far` 或 `rack_far_to_near`。

## 4. 动作拆分

`motion_bounds.start_state` 与 `end_state` 都要记录：位置与画面区域、姿态与朝向、重心、双手状态、道具状态、世界运动矢量、屏幕运动方向和摘要。中间变化按先后写入 `motion_beats`。

近身打斗默认按“起势 → 发力 → 接触 → 反馈 → 结果”拆镜。若单个生成片段需要同时可靠表现三人各自独立的攻击、闪避和反馈，应继续拆镜。

## 5. 空间与运动连续性

- `world_vector` 描述故事空间中的真实运动，如“由门口向窗边”；`screen_vector` 描述画面二维方向，如 `left_to_right`。两者不可互相替代。
- 相邻镜头换机位后，屏幕方向可以改变，但必须能由场景轴线和机位方位解释。
- 越轴时设置 `axis_crossing: true`，并采用 `neutral_shot` 中性机位、`visible_cross` 明示移动过轴或 `reestablish` 重新建立空间。不得无说明地翻转人物位置和视线。
- 双人对白保持视线匹配；先用建立镜头说明人物关系，再进入单人或过肩正反打。
- 动作接点、角色朝向、服装状态、伤痕、道具所在手和道具状态必须跨镜继承。

## 6. 光线连续性

主光方向、色温、环境光、时间和天气属于场景锚点。每镜默认继承场景值，不在提示词中自由改写。只有剧情明确改变光线时才可设置 `lighting_override: true`，并写明原因。

正反打中的“左脸受光/右脸受光”取决于人物朝向和灯位；校验的是世界空间中的灯位一致，不是机械复制脸部亮面。

## 7. 切镜规则

同主体连续切镜若机位水平变化小于 30 度，且景别只变化一级以内，标记为潜在 Jump Cut。它是警告，不是绝对错误。

以下剪辑可显式豁免：`jump_cut` 有意跳切、`match_cut` 匹配剪辑、`impact_cut` 冲击剪辑。豁免必须服务于节奏或信息表达，不能用来掩盖连续性失误。

## 8. 多主体场景

三人以上场景允许一个全景或中全景建立空间关系。进入生成镜头后，默认拆成单人、双人、过肩和反应镜头；一个镜头内最多让两个主体执行不同的复杂动作。静止背景人物、群体同向运动和统一反应不计作独立复杂动作。

## 9. 台词与抽象信息可视化

优先从上下文寻找已有动作、物品状态、环境变化和人物反应来承载台词。不要默认让角色正对镜头口播。

若只有孤立抽象台词，可提出一至三个候选视觉方案，但必须：

1. 设置 `visual_inference.is_inference: true`；
2. 在 `additions` 列出新增意象；
3. 在 `rationale` 说明它只是候选表达；
4. 添加 `visual_inference` 风险标记。

候选意象不是原文事实。用户未选择前，不得把蜡烛、雨夜、墓碑等意象写回剧情设定。

## 10. 声音与画面分轨

旁白、对白、环境声、拟音和音乐意图独立记录。声音可以跨镜延续或先声夺人，但提示词不能依靠声音字段来补足本应可见的动作。画面提示词不混入字幕、旁白文案或拟音词。
