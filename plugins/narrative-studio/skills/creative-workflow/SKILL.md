# 创作项目流程

按用户目标执行完整工作流，也支持只完成指定阶段。不要强迫每次调用都走完整流程。

## 开始前

1. 确定项目类型（短剧/漫剧、绘本或其他）、素材范围、预期交付、受众、平台/时长、输出语言和限制。
2. 把本任务相关规格一次列出，并附可调整的推荐项。用户可以逐项回答或说“按推荐”；只在缺少会改变核心结果的信息时暂停。
3. 若已有项目，先读 `creative-projects/<slug>/project.json` 及已确认阶段产物；不要覆盖用户正文。若没有项目，则建议简短 slug 并在获准创建文件时建立项目目录。
4. 输入可为粘贴文本、单个 TXT/Markdown，或章节文件夹。读取所选范围；章节边界不清时先确认。原文副本只读保存，不改写来源。

项目级数据结构见 [references/project-format.md](references/project-format.md)，索引字段见 [references/project-index.schema.json](references/project-index.schema.json)。可扩展的视觉风格清单见 [references/style-profiles.json](references/style-profiles.json)。

## 流程门

完整故事到制作资料流程按需覆盖以下阶段，并在五个关键点等待用户确认：

1. **故事骨架**：确认故事目标、主要人物、因果链和结局方向后才扩写正文或改编稿。用户明确要求直接草稿时可跳过。
2. **剧本审核**：展示问题和建议，用户确认修改范围后再改稿。
3. **核心资产**：确认资产范围、主风格（仅在项目尚未选择时询问）和核心角色/场景后再锁定资产。
4. **分镜骨架与时长**：先确认场次、镜头组和时长划分，再展开镜头及提示词。
5. **最终制作包**：列出缺项、文件清单及版本，确认后交付。

在无需该阶段的任务中跳过对应确认点，并说明原因。分集剧本默认一集一批；用户可要求连续批量生成。

## 资料与记录

- 默认在当前工作区 `creative-projects/<slug>/` 建立项目；不要写入云端或其他工作区。
- 项目索引 JSON 关联来源、阶段、输出相对路径、版本和确认记录。Markdown 是故事/剧本正文的主要格式；资产、分镜清单使用 JSON；关键审核、资产和分镜/提示词交付可生成独立离线 HTML。
- 每项改编或分析结论标注原文来源（文件、章节、段落/行）；明确区分 `source_fact`、`inference`、`creative_addition`。没有来源证据时不要伪装成原文事实。
- 阶段更新采用新版本或新增文件，不静默覆盖既有审核稿。记录用户已批准的范围和待决问题。
- 报告生成规则见 [references/report-format.md](references/report-format.md)。

## 能力路由

- 原创故事、故事检查、角色动机、去 AI 味、事件提取、骨架、改编、分集剧本与剧本审核：读取 `../story-development/SKILL.md`。
- 分镜、分镜检查、镜头动作和图像/视频提示词：读取 `../shot-design/SKILL.md`。
- 固定资产、资产提示词与风格确认：读取 `../asset-design/SKILL.md`。
- 绘本故事、分页、插画和逐页微动作提示词：读取 `../illustrated-book/SKILL.md`。

按需读取对应领域 Skill，不要把所有参考规则一次性加载。没有要求生成媒体时，不调用生图、图生视频或视频生成工具。
